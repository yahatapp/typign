# Typign: 学習設計・入力計測・日本語IMEの調査

確認日: **2026-10-20**。企画段階の設計判断であり、実装・学習効果を検証済みという意味ではない。外部資料で確認できた事実と、Typignで試す設計仮説を区別する。

## 結論

初期対象は、デスクトップで**日本語の読みをローマ字で入力し、英単語・記号を混ぜて練習する人**。一般公開はするが、精密計測を保証する環境は実機検証したOS・ブラウザ・配列に限定する。

MVPはIME OFFで読みを打つモードに集中する。IME ONの自然な文章入力は将来の別モードにする。前者で伸びても、日本語変換やAIへの指示を書く業務全体が速くなることは、別の転移テストで確認する必要がある。

差別化の中心は「データをもとにコーチと練習を組み立て、未見文で確かめる」という検証可能なループ。スピード、正確性、苦手、新パターンの4種類をコンセプトに含める。製品の方針はLLMコーチ中心へ更新し、計算・判定・計画の制約検査は検証可能な処理として残す。[企画書](../product-concept.md)

4種類の分類や組み合わせは企画方針であり、下記の研究がその効果や最適な配分を実証したという意味ではない。限界速度での試行、新パターンの習得、共通の確認課題は、条件を記録して比較する。

ホームポジションのガイドは提供する。ただし通常のブラウザイベントで分かるのは入力・キー位置・時刻などであり、実際にどの指を使ったか、手がどこにあるか、キーボードを見たかは判定できない。画面の「推奨指」を本人の実際の指使いとして記録しない。

## 研究から使える知見と限界

| 確認した知見 | Typignへの示唆 | 直接には言えないこと |
| --- | --- | --- |
| CHI 2016の実験では、10本指を使わない参加者にも速い人がいた。指とキーの対応の一貫性などが高い成績と関連した。[1] | ホームポジションを学び直す入口を用意し、本人が続けられる入力を支える | 10本指だけが唯一正しい、全員を同じ運指へ変えれば速くなる、という保証 |
| CHI 2018の大規模オンライン転記課題は、打鍵間隔・誤り・キーロールオーバーなどの個人差を示した。[2] | 文字だけでなく2〜3文字の並びと時間を観測する根拠になる | 相関した並びを反復すれば学習効果が生じる、あるいは日本語にも同じ効果量があるという因果関係 |
| テキスト入力研究では、修正された誤りと残った誤りを分け、提示文・入力履歴・最終文を用いる計測が提案されている。[3] | 最終文が正しくても、途中のミスと修正負荷を消さない | Backspaceの回数だけですべての誤りや修正時間が分かること |
| 運動課題の原著研究では、ランダムな練習順序や日を分けた練習が保持に寄与した条件がある。[4][5] | 対象だけの連打にせず、別の文と翌日以降の再確認を入れる仮説を試す | 日本語タイピングで「5分」「60/20/20」が最適だという根拠 |

これらは主に転記・運動課題の研究である。仕事では、文章の構想、読み直し、IME候補の選択、注意の切り替えが加わる。練習文を写す能力と、考えながら自然言語を入力する能力を同じスコアで表さない。

## ブラウザで観測する層

### キーと文字を別に扱う

| 層 | 主なイベント・項目 | 観測できること／注意 |
| --- | --- | --- |
| キー操作 | `keydown` / `keyup`: `code`, `key`, `repeat`, 修飾キー、時刻 | `code`は物理キー位置を表す識別子。`key`は配列・ロケール・Shift等を考慮した値。どちらも最終的な日本語確定文字と同一ではない。[6][7] |
| 編集の意図 | `beforeinput`: `inputType`, `data`, 選択範囲 | 挿入、削除、貼り付けなどの区別に使う。環境やIMEによって発火しない／取り消せない場合があるため、これだけに依存しない。[8] |
| 実際の編集結果 | `input`と入力欄の値・選択範囲 | 入力後の文字列を照合する。プログラムによる値変更は必ずしも`input`を起こさないため、アプリ自身の更新も別に追跡する。[9] |
| IMEの編集中状態 | `compositionstart` / `compositionupdate` / `compositionend`, `isComposing` | 変換中の更新と確定済み文字列を分ける。変換中文字列を更新のたびに新しい誤りとして数えない。[10] |
| 測定状態 | focus/blur、visibility、一時停止、終了 | 中断や別タブへの移動を、遅い打鍵や改善として解釈しない |

物理キーボードの`code`と文字は一対一とは限らない。仮想キーボードや支援機器では、ブラウザが物理キーに近い値を割り当てることもある。[6] 「`code`が届いたから必ず物理キーボード」とも断定しない。

JIS/USでは記号や追加キーの位置が違う。W3Cは`IntlRo`・`IntlYen`なども定義している。[11] 配列は本人に設定してもらい、記号のガイドと物理位置の集計を分ける。配列変更後の傾向を同じ系列へ無条件に混ぜない。分割キーボードは形状、配列は論理配置であり、両者も同義ではない。

時刻は同じページ内の一貫した時計から経過時間として扱う。イベント時刻にはプライバシー保護による精度制限があり得る。[12] 1〜数ms程度の違いから、指の制御や疲労の原因を診断しない。

### 最小の生データ

練習欄へフォーカスした測定区間のみを対象にし、次を保持する設計が望ましい。

- セッション・フレーズID、教材版、許容表記の版、分析版、入力モード、練習の種類と目標、対象の練習履歴、ガイド有無、配列設定、テスト環境。
- ページ内の相対時刻、連番、イベント種別、`key`/`code`、修飾、`repeat`、composition状態。
- 編集前後の選択範囲、挿入・削除の差分、整合性確認用の文字列状態、計測適格フラグ。
- 中断・貼り付け・ドロップ・観測不整合など、除外理由と除外範囲。

全ページ・他アプリの入力を監視する設計にはしない。MVP教材をアプリ側の短文に限定すれば、私的・業務上の自由文を収集しなくても測定設計を試せる。細かなタイミング履歴も個人の行動データとして扱い、標準は端末内保存とする。

## ローマ字とIMEの境界

### MVP: 読みのローマ字入力、IME OFF

「し」の`shi/si`などの複数表記を正解にする。Mozcの公開テーブルにも複数の経路、促音、撥音、小書き文字の処理が存在する。[13] これは全IMEが同じ入力を受け付けることの証明ではない。Typignがサポートする表記集合を版付きで定義する。

一つの固定文字列で採点すると、正しい表記の違いをミスにしてしまう。読みを許容経路のグラフで表し、入力した経路に沿って判定する設計を推奨する。`n`の語境界、`nn/n'`、小書き文字、促音、英字との切り替えは個別のテストが必要。かなごとの候補を単純につなぐだけでは、語境界や持ち越しを誤り得る。

`shi → si`への選択変更は、タイポ減少と同一ではない。ローマ字文字数・打鍵数の速度は、同じ表記経路で比べるか経路別に表示する。日本語読みの完成量を補助表示するなら、計数単位を「表示した読みの文字数」などと固定し、モーラ数や一般的なWPMと呼び替えない。

混在教材では「日本語として読む範囲」と「英字をそのまま打つ範囲」を明示する。`README`をローマ字変換対象にするかどうかを推測で決めない。大文字・記号は実際の文字を判定し、Shift操作の負荷は別に観測する。

### 将来: IME ONの模擬仕事文

ローマ字からかな、候補選択、確定という処理は、1打鍵=1確定文字ではない。W3CのUI Eventsにも日本語の変換例がある。[14] ブラウザAPIだけでIMEの候補列や内部判断をすべて取得する前提にはできない。

将来モードでは、確定後の文章、総時間、実際に観測できた編集・composition区間を中心に扱う。変換中のSpace/Enter/Backspaceを、そのまま文字ミスや修正キーへ算入しない。`compositionend`だけを汎用的な確定判定とし、イベントが全環境で同じ順序になる前提も置かず、入力値と突き合わせる。[8][10]

このモードの「漢字変換を直した」「誤ったローマ字を直した」「言い回しを変えた」は完全に識別できない場合がある。「編集操作」として残し、根拠不足なら原因分類しない。IME OFFの成績とは別の系列にする。

## 正確性・修正負荷・速度の定義案

以下は**実装スパイクで再現例を検証して固定する製品上の計数規約案**。既存研究と区別して名付ける。自由編集と複数経路があるため、「初回に頭の中で何を意図したか」を完全に復元することはできない。

### 採点の基礎

英数字のMVPでは、比較対象文字をASCIIとして揃え、大小文字・空白・記号の扱いを教材に記載する。将来Unicodeを扱う際はUTF-16の長さをそのまま文字数にせず、正規化と書記素の規約を追加する。

対象フレーズの許容正解経路を`P`、最終文字列を`T`、置換・挿入・脱落を各1とするLevenshtein距離を`D`とする。複数正解では許容グラフとの比較が必要。最終正確性の仮式は、許容経路について最大となる`1 − D(P,T) / max(|P|,|T|)`。これは簡易な製品指標であり、論文[3]の全指標を実装したという意味ではない。空の教材・分母ゼロは測定対象外。

最小距離の解釈が複数あるとき、全体スコアは計算できても、「どの並びで誤ったか」は一意でない。特定のキー・並びへの割り当ては保留する。採用経路・同点規則・分析版を残し、内訳が推定なら表示する。

| 指標 | 推奨定義 | 必ず併記するもの |
| --- | --- | --- |
| 修正前を含む正確さ | 判定可能範囲で、`1 − (Ec + Eu) / (C + Ec + Eu)`を仮採用。`Ec`: 誤りと判断でき、その後に削除・置換された挿入文字数。`Eu`: 最後に残る編集誤り数。`C`: 最終整列で一致する文字数 | 根拠件数、対象範囲、判定できた割合。単純な「初回打鍵正答率」とは呼ばない |
| 最終文字列の正確さ | 前述の許容経路に対する正規化編集距離の補数 | 文字数、残存誤り数、採点モード |
| 修正操作数 | 実際の編集を起こした削除・置換トランザクション数。キーリピートによる連続削除も記録する | 操作の種類、削除文字数。単なるBackspace keydown回数とは分ける |
| 修正操作/100入力文字 | `100 × 修正操作数 / 文字を挿入した総数`。分母には後に削除された文字も含む。分母ゼロは未定義 | 分子・分母、集計単位。同一教材条件で比較する |
| 正しい入力文字/分 | 最終整列で一致した文字数を、修正を含む測定時間の分数で割る | 同じ教材群・表記経路・時間規則。余分な文字も正確性で併記する |
| 並びの誤り候補率 | 対象の出題機会のうち、判定可能な誤り候補があった機会数の割合 | 例:`ng: 8/40機会`。同じ機会で何度誤っても、機会率では1件 |
| 並びの所要時間 | 正しく直接入力できた2〜3打鍵について、対応する`keydown`の間隔／最初〜最後の経過時間の中央値 | 適格サンプル数、同じ並び・表記・条件。修正や中断を含むものは別扱い |

`Ec`を求めるには、挿入された各文字の由来と削除・置換を追跡する必要がある。正しく入力した文字を消す編集や、有効なローマ字経路を別の有効経路へ変える操作を自動で誤りにしない。再修正が複雑で解釈が割れる箇所は不明扱いにする。分母を小さくしてよい成績に見せないため、診断のカバー率を結果に出す。

この式は単純な英字・直接編集の基準例から始めるための候補である。`Ec`の復元が信頼できるまで、公開UIは「修正前を含む正確さ」を単一の断定スコアにせず、「観測された誤り候補数＋修正操作＋最終正確性」を提示する縮小案がある。[3]の分類をそのままIMEへ適用しない。

### `ing → ign`の扱い

誤キーをすべて弾く方式では、`g`が拒否された時点で`ign`という列が残らず、転置と単発の誤キーを区別しにくい。短文の自由編集と履歴を推奨する理由はここにある。

- `ign`を確定した場合: 最終文の距離は2。別の有効表記でなければ「`ng → gn`の転置候補1件」とも数える。文字誤り数2と、分類イベント数1を混ぜない。
- `ign`を打ち、`gn`を削除して`ng`に直した場合: 最終正確性は100%でも、誤り候補と削除・再入力は履歴に残す。
- `i`の後に`g`だけを誤入力し、すぐ消して`ng`を打った場合: 観測された誤りは分かるが、実際に`gn`の並びは発生していない。「転置癖」と断定しない。
- 表記経路の選択変更や複数の編集で同じ最終列になる場合: 文字列の候補分類に留め、原因・意図・指使いは述べない。

短い並びに置換・脱落・挿入の複数説明がつくこともある。分類の精度が足りなければ、「この並びの前後で修正が多い」という観測に戻す。

### 時間のルール

速度の測定区間は、フレーズの最初の適格な入力から明示的な確定までを初期案とし、修正・迷いを含める。提示から初打までの時間は別記録にする。毎回のEnter確定の負荷も同じ方式で揃える。

フォーカス喪失・明示的一時停止があったフレーズは、評価用の速度比較から外す。長い打鍵間隔を後から都合よく除いて「速いスコア」にしない。比較除外の閾値を使うなら分析前に固定し、表示する。学習中は停止・休憩をしやすくし、評価のために無理な継続を促さない。

「ミスによって失われた秒数」は厳密には分離できない。修正区間の推定は補助情報に留め、MVPの成果指標は修正操作と総時間を優先する。

## 個別メニューのルールと不確実性

初回は幅広い短文で観測し、出題機会の少ないキーを「最も苦手」と順位づけしない。誤り率だけでなく、観測機会数と複数回での再現を用いる。仮の十分条件は「30機会以上・3誤り候補以上・2セッション以上」。これは統計的な確定線ではなく、少数サンプルの断言を避ける製品上の暫定ゲートである。

候補の優先度は「普段使いそうな並び × 誤りの頻度 × 観測の厚み」を単純なルールで決め、速度は正確さが確保された候補の補助情報にする。実際の仕事での頻度を取得していない段階では、教材内頻度を本人の仕事の頻度だと言わない。

5分メニューの案は、30秒の設定・ウォームアップ、60秒の観測、120秒の選んだ種類の練習、60秒の別文確認、30秒の振り返り。各練習は単独でも選べるようにする。対象60%、既習20%、幅広い探索20%という比率は、苦手練習の教材構成案に限定する。4種類間の配分は固定せず、これらの時間・比率に最適性の保証はない。

限界速度での誤りと新パターンの初回の誤りは、練習条件別に記録する。普段の弱点候補は診断や共通の確認課題を中心に判断する。新パターンは本人がまだ慣れていない入力を指し、未見の評価文は文章が初めてという意味で区別する。評価文には、練習済みの並びを含めてよい。

同じ並びの単調な連打だけで終わらず、並び→単語→別の文へ移す。翌日以降も再確認する。[4][5]はその設計を考える出発点であり、Typign固有の学習効果は未検証。疲れを自己申告でき、休憩・終了しやすい体験を設ける。

観測表示例: 「`ng`を含む40機会のうち8機会に誤り候補。直近2回にも出たので今日はこの並びを練習」。仮説表示例: 「この並びを少しゆっくり打つ練習が役立つか試します」。禁止する断定例: 「右人差し指が原因」「脳が先走っている」「2週間で必ず改善」。

## 小規模で価値を確かめる計画

### 計測が信用できるかを先に確認

技術スパイクの段階で、`shi/si`、撥音境界、促音、大文字、記号、`ing/ign`、誤り後の削除、正しい文字の削除、選択置換、カーソル移動、途中終了、ペースト、リピート、IME誤投入、中断を記録する。人手で期待結果を付けたケースと、イベントから再計算した結果を突き合わせる。

自動テストはイベント再生や状態遷移の整合性を確認できるが、実際のOS IMEの発火順序を保証しない。初期の動作保証はChromeを軸にWindows/macOS・JIS/USを実機で確認し、未確認の環境に精密診断を約束しない。

### 続けられるか、改善するかを分ける

| 検証 | 方法 | 次の判断に使うもの |
| --- | --- | --- |
| 理解と需要 | 5〜8人程度に、困る場面・既存の対処・練習したい理由を聞き、結果画面を説明してもらう | 数値の意味と選択理由が伝わるか。業務文の提出は不要 |
| 基準値 | 練習前の未見教材を別日に複数回測る。同じモード、長さ、記号密度、対象並びの密度を揃える | 日ごとの揺れと開始水準を把握する |
| 有用性の探索 | 10〜20人程度・約2週間を仮案に、同じ時間の標準練習Aと個別練習Bをユーザー内で反復。順番をランダム化／釣り合わせる | 利用者ごとの誤り候補率、修正操作、速度、継続・納得感 |
| 保持と汎化 | 練習直後に加え、翌日以降・終了後に未見の等難度フレーズを使う | 暗記した文の伸びと、別文への広がりを分ける |
| 実務への転移 | 別枠でIME ONの短い模擬文書を入力する。さらに自由作成を扱うなら構想時間も区別する | ローマ字練習以外で修正負荷が変わるか。業務効率と同義にはしない |

学習には持ち越しがあるため、A/Bの順番を変えるだけで因果効果を完全には分離できない。教材セット、日、順番、基準値を記録し、ユーザー内の反復は探索的な比較とする。練習効果の強い主張には、より大きい参加者数と並行群など別設計が必要になる。

参加者の多い人が全体を支配しないよう、まず各ユーザーの変化を集計し、個人別の分布を確認する。最高記録だけを使わず、改善しなかった人と中断者も報告する。小規模なので有意差だけで成功・失敗を決めない。

公開後の投資判断の仮ゲートは、(1)計測の誤判定が許容可能、(2)多くの協力者が次の練習の理由を説明できる、(3)複数の未見テストで修正量の減少傾向がある、(4)そのために大きく減速していない、の4点。具体的な減少幅・速度の非劣性幅は、基準値を観測した後、比較試験の結果を見る前に固定する。5分という継続容易性と、学習効果の有無は別々に評価する。

## 複雑すぎる場合の縮小順

1. **残す:** 複数正解の許容、短文編集、最終正確性、修正操作、正しく完成した量、保存・削除、ルール出題。
2. **限定する:** 誤り候補の復元は、履歴と経路が一意に対応する区間のみ。曖昧な箇所は全体の編集負荷に留める。
3. **後回し:** 厳密な初回正確性の単一スコア、細かい転置原因の分類、修正損失秒数、運指の自動評価、IME変換ミスの分類。
4. **公開しない状態:** 有効なローマ字表記を誤りとして診断する、最終正解になったら途中のミスが消える、未計測の指使いを断定する。
