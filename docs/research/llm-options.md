# LLM連携の実現性

確認日: 2026-10-20。公式資料を実際に取得して確認。これは設計調査であり、Typignの利用承認取得や実機での推論検証は行っていない。

## 結論

LLMコーチを製品の中心にする方針へ更新した。MVPから、根拠付きのセット提案、会話による変更、結果の振り返りを一方式で検証する。計測・集計・計画の制約検査はプログラムが担う。提供方式の最終決定までは端末内LLMを第一候補とし、運営側が推論費を負担しない元の方針を維持する。

前回案の「LLMはMVP後の補助機能」は、この方針で置き換える。未対応時の標準セットは回復手段として残すが、AIコーチを提供・検証したことにはしない。

### Sign in with ChatGPT

現在は公式のSign in with ChatGPTと、ユーザーのChatGPTプランで対象のResponses APIリクエストを実行する機能が存在する。したがって「ChatGPTログインから推論する手段は一切ない」という説明は正しくない。ただし、本人確認と推論への同意・利用資格は別である。[公式Quickstart](https://developers.openai.com/siwc/quickstart)

公式の公開説明は、OSS・ローカル実行のアプリ向けの経路と、選定パートナー向けWebサイト連携を区別している。リモートでホストするアプリや有料アプリには申請の案内があり、公開サイトのTypignで直ちに利用可能とは確認できない。コードをOSS化するだけで、ホスト型サービスの条件を満たすと解釈しない。[ChatGPT plan usage概要](https://developers.openai.com/siwc/token-sharing-open-source)、[Webサイト向け仕様](https://developers.openai.com/siwc/website)

対象利用者のプラン・権限・残り枠にも依存する。ChatGPT Freeの全利用者が使える、無制限に使える、あるいはログイン成功だけで推論可能とは約束しない。既存会話を取得する権限も含まれない。[公式統合例](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)

**判断:** MVPの必須要件から外す。一般公開サイトとして利用できる承認・契約・トークン保護方法を確認できたら再評価する。ローカル版を将来作る場合は別の候補。認証は練習開始の条件にしない。

### ブラウザの内蔵LLM

Chrome Prompt APIは現在Webページ向けにも提供され、日本語を指定できる。ただしOS、空き容量、GPUまたはCPUなどの条件があり、全ブラウザ・全端末向けの基盤にはならない。利用可否を実行時に検出し、モデル取得の開始・進行・中断を表示する。正式な対応状況と日本語コーチングの品質は別に検証する。[Chrome Prompt API](https://developer.chrome.com/docs/ai/prompt-api)

**判断:** MVPで最初に検証する推論方式の候補。日本語で目標を受け、根拠を読む、制約付きのセットを提案する、変更を受けて組み直すところまで確認する。未対応・低速・失敗時には標準セットへ戻す。APIが日本語に対応することと、このコーチ体験の品質が十分であることは別に検証する。

### WebLLM

WebLLMはWebGPUを使ってブラウザで推論でき、Web Workerへ処理を分離できる。初回のモデル取得やキャッシュが必要。採用モデルの日本語品質、メモリ、ライセンス、配布元を個別に確認する。[概要](https://webllm.mlc.ai/docs/index.html)、[初期ロード](https://webllm.mlc.ai/docs/user/basic_usage.html)、[Worker・キャッシュ](https://webllm.mlc.ai/docs/user/advanced_usage.html)

**判断:** Chrome内蔵モデルで要件を満たせないときの次候補。MVPに複数ランタイムを同時搭載しない。モデルの取得サイズを先に表示し、タイピング中の推論を避ける。

## 選択肢の比較

| 方式 | 運営の推論費 | 利用者側の条件 | 企画上の扱い |
| --- | --- | --- | --- |
| ルール＋監修済み短文 | なし | 通常の対応ブラウザ | 計測・候補作成・失敗時の標準セット |
| 集計結果と相談用プロンプトのコピー | なし | 自分のAIサービスを手動で利用 | 小さな追加候補。送信内容を確認してコピー |
| Chrome Prompt API | サーバー推論費なし | 対応Chrome・端末・モデル取得 | MVPで検証する第一候補 |
| WebLLM | サーバー推論費なし | WebGPU・モデル取得・十分な資源 | 端末検証後に採否判断 |
| ChatGPTプラン連携 | ユーザープランの枠等を使用 | アプリの利用資格＋利用者の同意・プラン | 公開Web版では承認条件を確認するまで保留 |
| ユーザー持込APIキー | 利用者にAPI課金 | API契約・通信方式・秘密情報管理が必要 | 選択肢に含めるか未決。全利用者の必須条件にはしない |

コピー方式はChatGPT API連携ではなく、ユーザー自身がAIサービスへ貼り付ける機能。結果の自動取り込みは含めない。ローカル保存された情報でも外部AIへ渡せばそのAIサービスで処理されることを明示する。

## LLMに任せる部分

入力は原則として計算済みの集計に限定する。例: 「`ng`の出題40回中8回で誤り候補、直近2セッションでも再現、ただしサンプル少」。元の文章、完全なキーイベント列、個人や会社の情報は標準入力に含めない。

LLMは分析の進行役として、比較する条件や確認したい仮説を選び、許可された集計操作を使って説明・セット提案を行う。正確性・誤り率の数値計算は分析処理に任せ、観測できない原因や学習効果を断定しない。

最小の操作は、対象の根拠取得、条件付き比較、後日の確認対象の取得、セット候補の取得、計画の検査とする。native tool callingに依存せず、構造化した操作候補をアプリが検査して実行する方式も検証する。任意SQL・コード実行は不要。計画には根拠ID・教材ID・練習の種類・時間を含め、本人が選んだ版と実施結果を保存する。[内部APIの案](../architecture.md)

生成された文には、文字数、許可文字、指定した練習対象の含有率、読みと表記の一致、教材としての適切さを検査する。学習効果を比較するテスト文には生成文を混ぜない。無効な文は固定教材へ戻す。

## 導入を判断するための小さな検証

1. ローカルで作った匿名の集計20例で、根拠付きセットの作成と条件変更を確かめる。
2. 数値の捏造、観測できない指使いの断定、指定練習対象の欠落が無いか確認する。
3. 対象端末で初回取得、2回目以降の応答、失敗、キャンセル、練習画面の応答性を測る。
4. ユーザーが次の練習を理解し、時間・重点を会話で変え、次回に前回の結果を引き継げるか確認する。

合格基準は実験前に決める。単に「AIが動いた」を導入理由にせず、定型文より理解や継続に寄与するかで判断する。Prompt APIとWebLLMは異なる実行方式なので、Worker対応を共通と仮定しない。
