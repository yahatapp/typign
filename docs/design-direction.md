# Typign UI設計方針

## 機能名・データ・操作を中心にする

アプリUIにはタグライン、文章調の見出し、挨拶や励ましの装飾文を置かない。見出しは「セット」「練習」「記録」「分析」のような機能名、操作は「開始」「変更」「根拠」のような短いラベルにする。重点・対象・時間・状態はラベルと値で示す。

例として、「今日は、打ち直しを減らす。」という見出しは置かず、「重点：正確性」「対象：ng」「時間：5分」「状態：提案」と表示する。入力対象となる練習文と、相談・根拠説明・振り返りに必要なコーチの回答はこの制限の対象にしない。

## 設計上のメンタルモデル

画面のメンタルモデルは、**計画、実施内容、結果、次の課題が残るトレーニングノート**とする。これは情報の構成を決める考え方とし、画面にノート風の文章や語りかけを配置する理由にはしない。コーチは記録と本人の希望からセットを提案する。

PCを前提に、中央でセットを読み、隣で理由を確認・相談できる広さを使う。数値を並べた総合ダッシュボードを入口にするより、「今日何をするか」を最初に把握できる画面を目指す。

## 主要画面

| 画面 | 主に見るもの | 主な操作 |
| --- | --- | --- |
| セット | 練習の種類・対象・時間・状態、選択理由 | 時間・重点を変更し、セットを確認して開始 |
| 練習 | 入力対象、入力欄、今回の目的、進行状態 | 打つ、一時停止する、終了する |
| 記録 | 計画の狙い、実施内容、確認結果、次回の一点 | 過去の提案と結果を読む |
| 分析 | 条件を揃えた推移、対象ごとの根拠、未確認事項 | 対象と期間を選び、コーチへ質問する |

個人データの保存・書き出し・削除、コーチが覚えている目標や希望は設定から確認できる。分析と相談の文脈を共有し、同じ対象を何度も説明し直さなくてよい設計にする。

### セット画面

左は小さなナビゲーション、中央は練習セット、右は根拠と相談を表示する領域。狭いウィンドウでは縦に並べ、根拠は開閉できるようにする。

練習の種類・対象・時間を一覧にし、重点と提案状態をラベルで示す。開始ボタンを主な操作として目立たせる。数値の細部やコーチの説明は、根拠を開いたときに読めるようにする。

相談例は「今日は5分にして」「正確性を重視したい」「なぜこの練習なのか」。変更時はセットをその場で更新し、何を変えたかを見せる。未適用の提案と、本人が開始したセットを区別する。

### 練習中は入力へ集中する

入力対象と入力欄を中央へ置く。目的の表示は短くし、スピード練習では速度、正確性練習では正確さと条件を満たした速度を見せる。診断やコーチの長文は終了後に読む。

計画やコーチの処理が失敗しても、進行中の入力を失わない。通信や推論の待ち時間で入力欄を止める設計にしない。

## 白黒と余白を基調に、操作部分へエッジを使う

以下の値は初稿のデザイントークン案。完成値として固定せず、PC画面で読みやすさを確認する。

| 要素 | 初稿の案 |
| --- | --- |
| 背景 | 白〜わずかに温かい白。本文との明度差を確保 |
| 主要文字 | ほぼ黒。重要な値と文章は薄いグレーへ落とさない |
| 補助色 | 無彩色を中心にする。状態は色だけでなくラベルや線種でも区別 |
| 外形 | 角は0〜4px程度。四角いセットと、揃った余白 |
| 枠 | 通常の区切りは細く、操作や選択のまとまりは1〜2px程度 |
| 影 | 主操作等へ短い、ぼかしのない影を限定して使う |
| 文字 | 日本語の本文は読みやすいサンセリフ。数値・入力列には等幅も使用 |
| 密度 | 本文を十分な大きさで置き、余白と罫線で見出し・理由・データを分ける |

ネオブルータリズムの要素は、全要素を太枠にすることではなく、開始ボタンやセットの境界がはっきり分かる形で取り入れる。グラフの軸・目盛・比較線まで太くせず、データを読む部分は静かにする。

操作状態は黒い面と白い文字、通常状態は白い面と黒い文字を基本にする。派手なグラデーション、ネオン、報酬演出、動き続ける装飾は使わない。キーボードフォーカスは明示し、入力の正誤は色以外でも伝える。

## 自然言語は相談・根拠説明・振り返りで使う

通常画面のセット提案は構造化して表示する。コーチとの相談を開いたとき、選択した根拠の説明を求めたとき、結果を振り返るときに自然言語を使う。回答は対象・件数・条件に結び付け、「あなたは右手が苦手」といった観測できない断定を避ける。

セット画面では項目と値、分析では件数と比較条件、振り返りでは前回の狙いとの関係を示す。相談例や説明文を常設して余白を埋めず、判断や操作に必要な情報だけを出す。

## 画面案で確かめること

- コーチの提案、実行するセット、開始操作がすぐ分かるか。
- タグラインや文章調の見出しがなく、機能名・値・状態・操作で構成されているか。
- 時間の変更でセットがどう変わるか、確認しやすいか。
- 根拠を開いても、今日の目的を見失わないか。
- 白黒の中でも、操作・選択・データの階層が読み取れるか。
- 強い枠や影が本文や数値の視認性を妨げないか。

会話内の画面案には架空データを用いる。実際のLLM応答や、検証済みの学習効果を示すものではない。
